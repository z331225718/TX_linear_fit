第 1 章 · 为什么

问题定义

我们只有一条波形，却想知道四件事

人话

示波器给我们的只是一条上下起伏的线。但工程师真正关心的是：这条线的「形状」是谁造成的、能不能补救、补救后还剩多少余量。

① 通道/发送端把符号拖成了什么样？

→ 提取线性拟合脉冲 p[k]：一个理想单位符号经过整条链路后的样子（含前后游标）。

② 能不能用均衡器把它救回来？

→ 求一个分析侧 FFE（可加 DFE），观察均衡后星座是否张开。

③ 质量如何量化？

→ SNDR_fit、SNR_ISI、RLM、眼宽/眼高。

④ 频域长什么样？

→ 由脉冲反推测量派生传递函数：Nyquist 幅度、3 dB 带宽。

输入前提：波形必须是已知周期的确定性码型（PRBS7/13/15/31 或 Clock 类），否则无法重建理想符号序列，也就无法做最小二乘。

第 1 章 · 为什么
5
核心直觉

为什么可以用「最小二乘」把脉冲挖出来

人话

如果我知道录音里每个字是什么（符号序列 x），又听到了一段被房间弄糊的声音（波形 y），那我就能问：什么样的「房间指纹」h，能把 x 卷积成 y？ 这个问题写下来就是一组线性方程。

三步逻辑

  1. 把长波形按 UI 切齐、叠成矩阵 Y（每一列是一个符号周期）。
  2. 把符号序列排成设计矩阵 X（每一行是「延迟 r 个 UI 的那个符号」）。
  3. 解 Y ≈ P·X，P 就是脉冲在不同相位上的采样 —— 列优先展开即得 p[k]。

边界

这是诊断工具，不是一致性测试系统

必须说清楚

本工具是波形分析与算法验证工具，不是认证系统。报告可带三种语义标签：neutral＝不声明按哪家协议口径解读（默认）、ieee8023＝按 IEEE 802.3 口径标注、oif＝按 OIF CEI 口径标注。标签只改报告上的文字说明：不会自动选择协议参数、不会加限值、也不会给出 pass/fail 结论。

它能做

  • 发送端波形诊断与参数敏感性分析
  • 算法验证（与 MATLAB golden 逐项比对）
  • 实验数据归档（PNG + CSV + 自包含 HTML）

它不能做

  • 替代 VNA 的 S 参数测量
  • 凭一份波形证明 IEEE 802.3 / OIF CEI 合规
  • 代替规定滤波器、夹具去嵌与仪器流程

正式认证应核对：目标 PHY、测试点、标准版本、夹具去嵌、规定滤波器与仪器流程。标准条款与限值会随修订变化。
